## 2. What CSS was removed, and why

The restructure deleted the markup these matched. Left in place they would be exactly the
stale-selector class of bug this file has already been bitten by twice today (AD-05 R6,
R8), so they are gone rather than orphaned. **43 declaration lines across 5 classes, plus
one stale id rule.**

| removed | why |
|---|---|
| `.s-journeys-h` — base rule + its `@media ≤1023` and `@media ≤767` rules (3 rules) | the display headline "You cannot argue someone into caring about a river" came off the homepage with the restructure; the band now opens on `.s-journeys-say` |
| `.s-work-idx` — base, `@media ≤1023`, `@media ≤767` (3 rules) | the 12-column mosaic wrapper is replaced by `.s-run-split` |
| `.s-work-lead` — 15 rules, incl. every `.s-work-lead .s-*` descendant and both `:hover`/`:focus-visible` compounds | the placard anchor moved up to the band-3 umbrella frame; the compounds were split so `.s-work-rows a:hover .s-work-t` and `.s-work-rows a:focus-visible` survive intact |
| `.s-work-k` — base + 4 contextual rules | the kind column is retired; the group heads name the kind once |
| `.s-work-foot` — base + 2 `@media ≤767` rules | the closing act moved into the events line |
| `#work{background:var(--ground)}` | **the dangerous one.** `#work` is now band 3, whose ground is already set by `.s-statement`. The id rule would have out-specified nothing today (same hex) and silently mis-owned tomorrow. The running order's ground is stated by `#running{background:var(--ground)}` in the AD-04 block. |

The `/* ══ 5. WORK ══ */` header comment described the deleted mosaic ("01 is the placard;
02 to 08 are a ruled ledger beside it") and was rewritten to record what survives, what
went, and where the replacement lives — a stale comment is the same bug one level up
(AD-05 R6, R9).

Re-checked after the removals: **the set of CSS classes that are declared but match
nothing is exactly what it was before the merge** — 29 pre-existing, zero new.

### Deliberately NOT removed

- `.s-journeys-tail>*:first-child` / `:last-child`. The tail now has one child, so both
  match the same element and the AD-04 block's later `:only-child` rule (equal
  specificity, later in the file) wins. They are **inert, not orphaned** — the element
  exists — and deleting them would change what happens the moment a second child returns.
- `grid-template-areas:"n shot t k"` on base `.s-work-rows a`. The rule still matches live
  markup; only the `k` area name is unused, and `#running .s-work-rows a` in the AD-04
  block out-specifies it at every breakpoint. Editing it would move measured output for no
  behavioural gain. **Worth a follow-up ticket, not a merge edit.**
- `.s-run-more-t` exists in the markup with no CSS rule. That is the fork as approved;
  left at parity.

## 3. Judgement calls (not decided by rule)

1. **The footer's `#work` link was NOT changed to `#running`.** The fork retargets
   *"Projects and campaigns"* from `#work` to `#running`. The footer is band 12, and the
   brief requires bands 7–12 byte-identical. `#work` still resolves — to the WORK chapter
   opener the restructure created — so nothing is broken, only less specific. **This is
   the one place the fork's intent was knowingly not taken; it is a one-line change and
   needs a ruling, not a guess.**
2. **`<title>` kept from the live file.** The fork carries
   `Swechha - We keep the record - AD-04 restructure (working file)`. The live title
   stands.
3. **The AD-04 block carries more than the fifteen named classes** — overrides on
   `#running`, `.s-journeys-tail>*:only-child`, `.s-journeys-rack`, `.s-journeys-fig img`
   and `#running .s-work-rows*`. All were taken, because they are load-bearing: the k
   column retirement and the phone re-crop (4:3, which is what brings journeys inside the
   900 cap) live there. Taking only the fifteen would have shipped a broken grid.
4. **The AD-04 block header comment was rewritten.** It read *"Working file — delete
   before deploy."* Left as-is on the live page that sentence is both false and an
   instruction to delete the chapter. It now records the merge, and records that the chip
   and the variant scaffolding must never follow it in.
5. **Excluded harness.** The fork's fixed mustard working-file chip (rule + `<div>`) was
   dropped; `grep` for the class name returns 0 in both CSS and markup. There is no `json`
   class anywhere in `_ad4/*` — the only occurrence of the word is the filename
   `2026-08-20-art-direction.json` inside a comment, which is prose and stays.
6. **`.s-ticker-stamp` has no CSS rule and must not get one.** It survives in the markup
   as the R2/R3 repair intends; AD-05 deleted the two rules that used to sit there and
   left a comment in their place. Verified: one flex item, comment intact.
